## 1. 一句话

> 两名剑客在一条线上对峙。谁先露出「一瞬」的破绽，谁就挨刀。
> 心流不是血条，而是你出手时那几帧的余裕——越静，越准。

**一句话玩法**：读前兆、辨虚实，在 0.2 秒内选择「斩」或「架」；用冷静与正确读招积累心流，换取更宽的容错窗口，连破五位对手。

---

## 2. 设计支柱

1. **静—动—余**：每场对决是三拍循环。静（对峙、读前兆）→ 动（一瞬决断）→ 余（刃鸣/收刀/呼吸），再进入下一拍。
2. **输在贪，不在手慢**：乱按、贪刀、架早都会被明确惩罚；奖励耐心与正确读招，而不是手速。
3. **心流是「看得更清」**：只放宽窗口与提示强度，不提供免伤、不改时间流速，避免变成「攒能量开无敌」。
4. **每一刀都可归因**：中刀时玩家能说出「我架早了 / 我贪了 / 我没读出来」，而不是「不知道怎么就死了」。

## 3. 主题「心」的机制映射

活动主题为「心」，本项目把「心」落成四个可玩的机制，而不是叙事标签：

| 主题面向 | 机制载体 | 说明 |
|---|---|---|
| 心流（注意力余裕） | 心流值 0–100，三档 | 越专注，出招与格挡的容错窗口越宽，前兆线索越清晰 |
| 不动之静 | 面对虚招不出手 | 看破虚招回心流；「忍住」本身就是操作 |
| 决心 | HP、金币与连战「残心」 | 跨场保留的 HP、局外金币、连胜叠加的残心，构成 Roguelike 的取舍 |
| 读心 | AI 性格化节奏与虚招 | 逼玩家读「人」的节奏，而不是背帧表 |

> 不做「心情/好感/对话选择」系统：与一秒决断的玩法节奏冲突。

## 5. 核心循环

### 5.1 单场（30–90 秒）

```
对峙(IDLE) ──► 试探(构/虚招/抢攻) ──► 决断(斩/架/不动)
    ▲                                        │
    └──── 结算(命中/被架/刃鸣) ◄── 心流变化 ◄─┘
                     │
              一方 HP 归零 ──► 胜负
```

### 5.2 单局（8–12 分钟）

```
标题 → 选角色 → 阶梯第 1 场 → 三选一「心得」 → 第 2 场 → … → 第 5 场（关底） → 结算 → 解锁
                │
                └─ 中途败北 → 结算（按击败数给「金币」，残心清零） → 回标题
```

### 5.3 一个回合的例子（帮助理解，不是教程文案）

1. AI 进入「构」（前兆 18f）。
2. 玩家在第 6f 按「架」。
3. AI 在第 8f 取消出刀（虚招），玩家架落空 → 心流 −8，收架 8f。
4. AI 立刻抢攻，再次进入「构」。
5. 玩家这次在第 13f 按「架」，架住 → 心流 +7，AI 被架硬直 32f。
6. 玩家反击命中 → AI −1 HP。
7. 双方退回对峙，心流档位变化，下一次前兆的线索更清晰。

> 这一回合同时用到了：读前兆、辨虚招、承担空架代价、把握反击窗、心流滚雪球。

## 6. 战斗系统规格

### 6.1 场地、站位与时间基准

- **1D 横线**：两人固定在一条线上，间距固定（视觉 160 px），**无自由移动**。
  - 理由：移动会引入空间维度与额外按键，违背「易上手」；固定间距让对决聚焦在「读与断」，也符合居合「一足一刀」的意象。
- **斩 = 踏込**：出刀时角色向前位移（纯表现），判定上无距离概念。
- **时间基准**：60 Hz 物理帧，所有窗口以**整数帧**计；表现层可换算为 ms。
- 不设场景边界、地形、高低差。

### 6.2 状态机

| 状态 | 含义 | 进入 | 离开 |
|---|---|---|---|
| `IDLE` | 对峙待机 | 初始 / 收招结束 | 斩、架、受击、刃鸣 |
| `COMMIT` | 构（前兆） | 按斩 | 前 5f 可按架取消进 `GUARD`；否则转 `SLASH` |
| `SLASH` | 斩击判定 | COMMIT 结束 | 判定窗结束 → `RECOVERY` |
| `RECOVERY` | 空挥/被架硬直 | 斩击结束 | 计时结束 → `IDLE` |
| `GUARD` | 架（有效窗） | 按架 / 取消 | 持续窗结束 → `GUARD_REC` |
| `GUARD_REC` | 收架 | 架窗结束 / 空架 | 计时结束 → `IDLE` |
| `HITSTUN` | 受击硬直 | 被命中 | 计时结束 → `IDLE`（含无敌） |
| `CLASH` | 刃鸣弹开 | 双方判定窗重叠 | 计时结束 → `IDLE` |
| `SPELL` | 符卡发动硬直 | 按符卡 | 计时结束 → `IDLE`（不无敌，可被斩中） |
| `DOWN` | 败北 | HP 归零 | 本场结束 |

规则：
- `COMMIT` / `SLASH` / `RECOVERY` / `GUARD` / `GUARD_REC` / `HITSTUN` / `CLASH` / `SPELL` 期间**不接受新输入**。
- 状态切换只发生在物理帧边界，保证可重放。

### 6.4 判定矩阵

每次 `SLASH` 判定窗的**第一帧**做一次接触结算（同帧内只结算一次）：

| 攻方 | 守方状态 | 结果 |
|---|---|---|
| 斩 | `IDLE` | 命中：守方 −角色伤害（1 或 2），进 `HITSTUN` |
| 斩 | `COMMIT` | 命中：守方攻击取消，进 `HITSTUN`（先手胜） |
| 斩 | `SLASH` 判定窗 | **刃鸣**：双方弹开 12f，无伤，各 +6 心流（递减） |
| 斩 | `RECOVERY` | 命中（确定反击） |
| 斩 | `GUARD` 有效窗 | **被架**：攻方 32f 硬直；守方 8f 后可行动；攻方 −8 心流，守方 +7 |
| 斩 | `GUARD_REC` / 启动前 | 命中 |
| 斩 | `SPELL` | 命中（符卡硬直期间不无敌，可被趁隙斩中） |
| 斩（符卡破防） | `GUARD` 有效窗 | **命中**：无视架势；符卡效果照常结算 |
| 斩 | `HITSTUN` / 无敌 | 无判定 |
| 斩 | `CLASH` | 无判定 |
| 架 | 对方真斩且接触落在架窗内 | 架住（同上「被架」） |
| 架 | 对方虚招 / 待机 | **空架**：−8 心流，收架 8f |
| 不动 | 对方虚招 | **看破**：+10 心流 |
| 不动 | 对方真斩 | 命中 |
| 同帧斩+架 | — | **架优先**（防御优先原则） |

补充：
- 接触判定使用「斩判定窗第一帧」的守方状态；`GUARD` 启动 1f，所以只有「在接触帧当帧才按下」才会撞上前摇——这是为了让「看见再按」不再被启动帧吃掉（2026-10-20 由 2f 降到 1f）。
- 刃鸣优先级高于命中：先判「双方是否都处于 `SLASH` 判定窗」，再判单方命中。
- 被架后的攻方 32f 硬直内，守方 8f 收架结束即可反击，形成确定惩罚。

### 6.5 输入

| 输入 | P1 默认键 | P2 默认键 | 语义 |
|---|---|---|---|
| `duel_attack_*` | J | 小键盘 1 / I | 斩（进入 `COMMIT`） |
| `duel_guard_*` | K | 小键盘 2 / O | 架 |
| `duel_spell_*` | L | 小键盘 3 / P | 符卡（每场 1 次，见 §6.11） |
| `ui_*` | Enter / Esc 等 | — | 菜单、暂停、重开 |

手柄：斩 = A，架 = B，符卡 = Y；暂停 = Start，重开 = Back。

- **按下沿触发**，长按无效（V1 不做蓄力）。
- **4f 输入缓冲**：在硬直/收架结束前 4f 内按下的键，会在可行动的第一帧执行，减少「按了没反应」的挫败。
- **虚招（进阶技巧，不教学）**：`COMMIT` 前 5f 内按架 → 取消出刀并进入 `GUARD`，耗 5 心流。用于「假装出刀、实则架住对手的反击」。
- 键位全部走 GUIDE Action，不硬编码键名；支持改键。

### 6.6 心流

**定位**：心流 = 注意力的余裕 = **容错时间**。它不提供免伤、不改变时间流速，只放宽窗口与提示（心得 U06「见切」是唯一的免伤例外）。

| 档位（内部代号） | 区间 | 斩前摇偏移 | 架持续 | 完美格挡窗 |
|---|---|---|---|---|
| 散 | 0–33 | **+6f** | 12f | 3f |
| 静 | 34–66 | 0 | 16f | 4f |
| 流 | 67–100 | **−6f** | 20f | 5f |

- **心流主要在进攻端兑现**：两端前摇差 12f（200ms），玩家从「我出手变快了」直接感知；防守端架持续差 8f（133ms）是次要补偿。
- 前摇有 **8f 下限**（`DuelSim.COMMIT_MIN_FRAMES`）：高心流叠加「疾构」也不会出现读不到的出手。
- 斩前摇为相对各角色基准的偏移；玩家 A 基准 18f，即散档 24f、流档 12f。
- 开局 40（静）；**每场重置为 40 加残心保证**（见 §8.3），不跨场累积。
- 自然恢复只在「待机且最近 3 秒内有操作」时生效；完全干等会先停止恢复、随后转入惩罚，避免「站着不动最赚」。
- 玩家与对手各自独立计算；对手心流同样影响其窗口。
- **但对手不吃「流」档的 −6f 加速**（`FighterData.flow_speeds_commit = false`）：AI 架住/完美格挡会涨心流，一旦进「流」档，18f 前摇会被压成 12f（200ms），玩家看见也来不及。对手只吃「散」档的 +6f 惩罚——低心流变慢是它的失误代价，高心流不该变成玩家无法反应的加速。这同时给「心流是玩家的成长」留出单向优势。
- 看破提示的提前量只来自心得 U05「先读」，不再随心流档位变化——避免同一加成有两条来源。

**收支表**

| 事件 | 心流变化 |
|---|---|
| 待机自然恢复（最近 3 秒内有操作） | +1 / 24f |
| 出刀（按下斩的瞬间） | −4 |
| 架住 | +7 |
| 完美格挡（接触发生在架生效后 3–5f 内，随档位） | +12（**替代** +7） |
| 连续完美格挡 | 每次额外 +3，单场上限 +9 |
| 看破虚招（对手虚招时你保持不动） | +10 |
| 对手处于 `COMMIT` 时你保持不动 | +3 / 秒（每 20f +1，单场上限 +15） |
| 刃鸣 | +6，同场连续刃鸣递减为 +4 / +2 / 0 |
| 被架 | −8 |
| 空架 | −8 |
| 中刀 | −15（残心可减免，见 §8.3） |
| 发动符卡 | −30 / −35 / −34 / −40（按角色，见 §6.11） |
| 连续无输入超过 3 秒 | −1 / 20f（3 / 秒） |

**防雪崩**
- 单场心流下限 15；残心会把它抬高（3 层 → 33，直接锁定「静」档）。
- 中刀后 2 秒内，空架不再扣心流（避免「被压着打→越打越崩」）。
- 心流不改变移动/时间，避免与「容错」的承诺冲突。

### 6.7 HP 与胜负

- 玩家基础 3 HP（角色 C 为 4）；对手依次 3 / 3 / 4 / 4 / 4 HP。
- **伤害按角色不同**：A / B 每刀 **1**；C 每刀 **2**，并附带 **12f 追加硬直（破势）**——被 C 砍中者硬直 24 + 12 = 36f。C 用「比 A 慢 3f、每刀多耗 1 心流」换「一刀顶两刀 + 更长硬直」，4 HP 因此有实际价值，而不是单纯多挨一刀。
- 「追击」心得（U07）与符卡伤害为**覆盖**而非叠加：`damage = maxi(角色伤害, 加成值)`。
- **HP 跨场保留**；每胜回复 1 HP（不超过角色最大 HP）。「复元」心得可把回复量提到 2。
- 受击后 400ms 硬直 + 200ms 无敌，防止连段与误判。
- 一方 HP 归零 → 本场结束；玩家败北 → 本局结束。

### 6.8 刃鸣（Clash）

- 双方 `SLASH` 判定窗重叠 → 双方弹开 12f，无伤，各 +6 心流（递减）。
- 表现：火花 + 强屏震 + 短促金属音（占位）。
- 设计意图：奖励「敢在同一瞬出刀」，同时用递减收益防止互相刷刃鸣拖时间。

### 6.9 虚招与看破

- **AI 虚招**：在 `COMMIT` 的 50–70% 处取消，回到 `IDLE` 或进入 `GUARD`；概率由 `feint_rate` 控制。
- **虚招代价**：取消后 AI 有 6–10f 额外硬直，玩家可抢攻——虚招不是无风险。
- **玩家应对**：不动（看破 +10）或晚架（等真斩再架）。
- **看破提示**：只提高前兆线索的**可辨识度**（视觉/音效强度、提前量），**不给「真/假」标签**。避免游戏退化成读 UI。
- 玩家的虚招（§6.5）是「取消进架」，用于钓对手反击，不与 AI 的「取消回 IDLE」完全对称。

### 6.10 手感与表现参数

| 项 | 值 | 备注 |
|---|---|---|
| Hitstop | 命中 6f / 被架 4f / 刃鸣 8f | 物理帧冻结，不影响判定结果 |
| 屏震 | 命中 0.30 / 被架 0.15 / 刃鸣 0.25 | 可在设置中关闭 |
| 镜头 | 固定侧视，命中轻微推近 | 视角见 §11 |
| 音效 | 斩 / 被架 / 刃鸣 / 受击 / 心流升档 各一 | 占位，见 §15 |
| 受击闪白 | 3f | 与无敌帧同步开始 |

### 6.11 符卡（每角色 1 张，与角色硬绑定）

符卡是**每场一次**的关键资源，不是连招素材。设计前提有两条：

1. **血量只有 3–4、普攻 1–2 伤**——「更大的数字」没有空间（3 伤对 3HP 是一击必杀，对 4HP 却与 2 伤等价）。所以收益必须做成**规则级**（必完美格挡 / 穿防 / 自动落刀），不能是数值级。
2. **风险必须和收益同量级，且必须是「明牌」**——藏起来的隐含惩罚（悄悄掉一档心流）只会让玩家觉得「用了更弱」，不会觉得「我在冒险」。风险统一由「可读的蓄力破绽」承担：发动/蓄力期间不无敌、可被抢刀打断，打断后次数不还、心流不退、再加 12f 惩罚硬直。

三张符卡与三位角色一一对应（名称与描述 PLACEHOLDER，见 §15.2）：

| 角色 | 内部代号 | 心流消耗 | 发动/蓄力 | 每场次数 | 效果 |
|---|---|---|---|---|---|
| A 均衡 | `spell_a`（架势） | 30 | 10f | 1 | 之后 **60f 内任意时刻的架都判定为完美格挡**，且架窗固定抬到 **30f** |
| B 快剑 | `spell_b`（疾风连斩） | 35 | 8f | 1 | 蓄力结束**自动出刀**，伤害 2 且**无视对方架势** |
| C 重剑 | `spell_c`（崩势斩） | 34 | **20f** | 1 | 蓄力结束**自动出刀**，伤害 **3**、+12f 硬直，且**穿防** |
| 5 关底 BOSS | `spell_boss`（崩势斩·极） | 40 | **14f** | 1 | 蓄力结束自动出刀，伤害 **3**、+12f 硬直，且**穿防** |

规则：

- **发动条件**：心流足够、本场次数未用尽、且处在 `IDLE`。心流不足或次数用尽 → 发动失败（`spell_failed`），**不扣次数**。
- **输入缓冲**：在收刀/架后/受击硬直里按下符卡**不算没按**——进入 `FighterData.input_buffer`（4f）缓冲，回到 `IDLE` 即发动；过期才报失败并让 HUD 那一行闪红 16f。这条是为了消灭「按了没反应，以为键坏了」。
- **不无敌**：所有符卡付完心流后进入 `SPELL` 蓄力状态（10f / 8f / 20f / 14f），期间**可被任一刀斩中**。
- **蓄力可被打断**：蓄力期间被命中 → 立刻驱散（`spell_interrupted`）并追加 `SPELL_INTERRUPT_PENALTY`（12f）惩罚硬直；次数不还、心流不退。一次符卡白给必须疼。
- **自动落刀**：斩类符卡（`spell_b`/`spell_c`/`spell_boss`）蓄力结束**自动**进入 `SLASH`，不需要再按一次。蓄力环会从外向内收，落刀前 8f（`SLASH_WARN_FRAMES`）转白——与普通「构」的预警一致。
- **穿防**：`unblockable` 只作用于那一刀，结算后立即清除；打在无效架（未过 `guard_startup`）上仍是命中。玩家的 `spell_b`/`spell_c` 与关底的 `spell_boss` 都穿防。
- **硬绑定**：`FighterData.spell_id` 指向角色自己的符卡（`spell_a`/`spell_b`/`spell_c` ↔ `char_a`/`char_b`/`char_c`，`spell_boss` ↔ `char_boss`），不存在通用符卡。
- **AI 只有关底持有符卡**：1–4 场对手 `spell_id` 为空，永远不会发动；关底持有 `spell_boss`，每场 1 次。
- **开局必须发得出来**：三张符卡的成本都 ≤ 对应角色的 `start_flow`（40 / 46 / 36）。这是硬约束——发不出来的符卡等于不存在。

#### 6.11.1 关底符卡的发动时机（AI）

- 只有三个「值得」的时刻会考虑：**能一击终结玩家**（玩家 HP ≤ 1）、**自己垂死**（HP ≤ 1）、**对峙超过 15 秒**该逼节奏。
- 到达时刻后按 `AiProfile.spell_chance`（关底 0.85）掷一次，失败不消耗、下个决策点再掷；成功后本场不再考虑。
- 14f 蓄力是全场最长的可读前摇：玩家看见脚下光柱与双环，正确解是在这 14f 内抢先出刀打断，而不是架（架不住）。

#### 6.11.2 符卡的表现

- **发动者**：脚下升起阵营色光柱（P1 紫 `#b79bff` / P2 粉 `#ff9bd0`），身体外两圈反向旋转弧；`SPELL` 蓄力状态下持续可见。
- **蓄力进度**：斩类符卡额外画一圈从外向内收的环，落刀前 8f 转白。玩家不需要数帧，只看「环白了大刀就落」。
- **架势安全区**：`spell_a` 生效的 60f 内，角色身上常驻一圈青白环，剩余时间用弧长表示——否则「必完美格挡」是纯隐形的规则。
- **发动瞬间**：以发动者为中心炸开双扩散环（约 0.6s 衰减），全屏极淡同色染色；同时播放降调开场音 + 高频金属余韵（P2 比 P1 更低一档）。
- **报幕**：屏幕中上方以 `◆ 符卡名 ◆` 显示 96f（1.6s），颜色分阵营，末尾淡出。只显示符卡名本身，**不加任何动词文案**（文案由人类提供，见 §15.2）。
- **HUD 四态**：`名称 ×剩余次数 (消耗)` 为就绪；蓄力中显示 `名称 ×1 ▶剩余帧`（紫）；已用显示 `名称 ×0`；心流不足整行降到 45% 不透明度。发动失败时该行闪红 16f。
- **被打断**：短促破音 + 半强度扩散环，提示「蓄力没了」。

## 7. 对手 AI

### 7.1 决策模型

- 每 6f 评估一次；输入是双方状态与「玩家行为统计」（近 30 秒的架率、出刀率、平均反应间隔），**不读玩家按键**。
- 意图集合：`WAIT` / `COMMIT`（真）/ `FEINT`（假）/ `GUARD` / `COUNTER`。
- 决策 = 性格权重 × 局势修正 × 随机扰动；随机数用固定种子，可复现。
- `reaction_ms` 下限 180ms；难度通过前兆时长、虚招率、反应时间、惩罚率调节。
- 玩家处于 `RECOVERY` 时，高 `punish_rate` 的 AI 会立刻出刀。
- 关底二阶段（HP ≤ 2）：攻击欲 +0.15、虚招率 +0.15、反应 −2f、决策间隔 −2f。

### 7.2 五场对手参数（内部代号，名称 PLACEHOLDER）

| 场次 | 代号 | HP | 前兆 | 攻击欲 | 虚招率 | 反应 | 性格 | 教学点 |
|---|---|---|---|---|---|---|---|---|
| 1 | 教学 | 3 | 20f | 0.30 | 0.03 | 15f (250ms) | 慢而规律 | 看前兆 → 架 |
| 2 | 急性 | 3 | 18f | 0.65 | 0.08 | 16f (267ms) | 抢攻、少防守 | 别贪刀；被架会挨打 |
| 3 | 老练 | 4 | 19f | 0.45 | 0.25 | 14f (233ms) | 反击型 | 虚招与晚架 |
| 4 | 虚实 | 4 | 18f | 0.50 | 0.45 | 13f (217ms) | 骗架、惩罚空架 | 心流管理；忍住 |
| 5 | 关底 | 4 | 18f | 0.60 | 0.35 | 12f (200ms) | 两阶段、全能 | 综合考试 |

- 五位对手的前兆统一在 **18–20f（300–333ms）**。旧值 12–15f（200–250ms）低于「看见→按键」的实际开销（视觉反应约 250ms，再加 1f 输入延迟与 1f 起架），玩家在物理上不可能架住——这不是操作问题，是前兆本身低于人类阈值。难度改由攻击欲、虚招率、反应帧与惩罚力度承担，而不是压缩可读性。
- 前兆差异只剩 2f（教学 20f vs 其余 18–19f），是有意为之：五场的区别读起来是「性格」而非「速度」。若实机仍嫌慢，优先回调第 4/5 场到 16f，而不是回到 12–13f。
- 前兆期间统一有 8f 的落刀预警（气环转白 + 「叮」），给已经盯着气环的玩家一个确认点；AI 出刀与玩家出刀共用同一套预警。
- **对手的高心流不会变成「无法反应的一刀」**：AI 架住、完美格挡、看破都会涨心流，但 `flow_speeds_commit = false` 让它只吃低心流的 +6f 惩罚、不吃高档 −6f 加速，前摇永远 ≥ `base_commit`（18–20f）。
- 首战礼让 3 秒（双方禁攻），攻击欲 0.30、虚招率 0.03、反应 250ms：先让玩家看清「构」与「气环」。
- 礼让结束显示约 42f（0.7s）的「开始」提示；首战 AI 再多等 30f 才可能出第一刀。
- **AI 命中玩家后强制间合**：教学 75f（1.25s）、普通 50f（0.83s）、关底 40f；期间 AI 不出刀，但可架。玩家仍可立即反击，不剥夺玩家的进攻节奏。
- **符卡只属于关底**：1–4 场不持有、不会发动（`spell_id` 为空，`spell_chance` 为 0）；第 5 场持有 `spell_boss`（见 §6.11），在最值得的时刻发动一次，14f 蓄力留给玩家抢刀打断。
- 五位对手的「剑型」差异只体现在参数与出招节奏，不新增按键或规则。

### 7.3 公平性约束

- AI 不读输入、不做「必架」「必闪」；所有反应经过 `reaction_ms` 延迟。
- AI 命中后强制间合，避免「一套连到死」；玩家对 AI 的连段不受此限制（玩家仍可追击）。
- 首战与教学提示保证「第一次中刀可理解」。
- 固定种子下整场可重放，便于复盘与自动测试。
- 提供「重开」与「降低提示强度」以外的辅助不做（避免改变核心博弈）。

## 8. Roguelike 结构

### 8.1 局内（Run）

- 5 场线性阶梯；第 5 场为关底。
- 每胜一场（第 5 场除外）→ 三选一「心得」。
- 场间可查看当前心得、HP、下一场对手代号。
- HP 跨场保留；每胜回复 1（「复元」为 2）。
- 失败即本局结束，可一键重开。

### 8.2 心得池（10 个，名称与描述 PLACEHOLDER）

| 编号 | 内部代号 | 效果 | 备注 |
|---|---|---|---|
| U01 | 架幅 | 架持续 +2f | 与心流档位叠加 |
| U02 | 疾构 | `COMMIT` −2f | 出刀更快，也更难被读 |
| U03 | 明镜 | 完美格挡心流改为 +18 | 强化连续完美 |
| U04 | 深流 | 开局心流 +10（上限仍 100） | 与 U03 可组合 |
| U05 | 先读 | 看破提示提前 +4f | 提高线索提前量 |
| U06 | 见切 | 受击时若心流 ≥ 50，消耗 30 抵消该次伤害（每场 1 次） | 保命 |
| U07 | 追击 | 命中后 3s 内下一刀 +1 伤害（每场 1 次） | 斩杀线 |
| U08 | 胆力 | 中刀后 5s 内心流不下降 | 抗压 |
| U09 | 先手 | 每场开场 3s 内 `COMMIT` −3f | 抢开局 |
| U10 | 复元 | 每胜回复 2 HP（替代 1） | 续航 |

- 同名心得**不叠加**（取最高/唯一）；三选一不重复出现已拥有项。
- 稀有度 V1 不做；先保证 10 个效果都能实现、可测。

### 8.3 局外（Meta）

- **货币「金币」**（灰盒版固定使用；「灵力」仅在后续确定 IP/世界观后再考虑改名，不在当前范围）：每击败 1 位 +10；通关关底 +30；无伤获胜额外 +10；每剩 1 HP +2。
- **金币是局外钱包**：`RunState.start_run()` 从 `MetaSave` 带入金币，每场结算后写回；失败、退出、重开都不丢失（M3 已实现）。
- 用途：局外解锁（M4 已做**解锁商店**，仍不做随机商品；当前 4 项，新增只需加数据）：
  - 角色 B：40 金币
  - 角色 C：70 金币
  - 起始心得槽（开局自带 1 个随机心得）：50 金币
  - 困难模式：通关一次后解锁（免费开关）
- **商店完全数据驱动**：每个条目是 `resources/unlocks/*.tres` 的 `UnlockItem`；`GameBootstrap` 启动扫描并注册到 MSF `"unlock"` 注册表，`Unlocks.catalog()` 只读注册表；新增条目不需要改代码/UI。
- **商店**：主菜单进入，显示金币、各条目的价格/已解锁/条件；购买调用 `MetaSave.spend()` + `add_unlock()` + `save()`。
- **设置页**：主音量 / 音效 / 环境音量、静音、全屏；写入 `MetaSave.settings` 并立即应用。
- **暂停**：对局中 Esc 打开暂停层（继续/重开/主菜单），暂停时 `DuelSim` 与 AI 不推进。
- **残心（连战加成，不是货币）**：
  - 每胜 1 场 +1 层；无伤获胜再 +1；最多 3 层。
  - 每层效果（可叠加，最多 3 层）：
    - 下一场**开局心流 +8**（与心得 U04 叠加，上限 100）。
    - **心流下限 +6**：3 层时下限 15 + 18 = 33，正好越过「散」档上界，等于每场都从「静」档起跳。

    - **架持续 +1f**。
  - 失败或主动重开清零；不写入存档，不参与任何消费。
  - 作用：把「连胜」变成**可感知的档位保障**——残心不是为了多打几刀，而是让你整局都在「静」以上，心流加成一直在线。

## 9. 角色

### 9.1 三位可玩角色（内部代号）

| 代号 | 定位 | `COMMIT` | 空挥 | 被架 | 架持续 | 斩耗 | 判定 | 伤害 | 破势 | HP | 开局心流 | 回心流间隔 | 符卡 | 特性 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| A | 均衡 | 18f | 20f | 32f | 12f | 4 | 5f | 1 | — | 3 | 40 | 24f | 架势（60f 必完美） | 标准，教学角色 |
| B | 快剑 | 16f | 18f | 28f | 11f | 4 | 4f | 1 | — | 3 | 46 | 22f | 疾风连斩（8f 蓄力·穿防） | 前摇短、收招快、判定窄 |
| C | 重剑 | 21f | 24f | 36f | 14f | 5 | 6f | **2** | **+12f** | 4 | 36 | 26f | 崩势斩（20f 蓄力·3 伤·穿防） | 血厚、判定宽、一刀顶两刀 |

- 表中 `COMMIT` 为静档基准，心流档位按 **+6 / 0 / −6f** 偏移（下限 8f）。
- 三人都遵循「待机自然恢复 +1/24f、出刀消耗心流」；C 的斩耗更高，换「2 伤害 + 破势 + 4 HP」。
- C 的定位修正：原设计「血厚但更慢且同伤害」导致多出的 1 HP 只够多挨一刀，没有收益。现在 C 用 3f 慢速与 1 点心流换 2 倍伤害和 36f 硬直，站桩换血的期望更高。
- 符卡与角色硬绑定，收益错开：A 补「守」（60f 内必完美格挡，把「看见再按」变成「提前摆好」）、B 补「快」（8f 蓄力后自动穿防一刀）、C 补「终结」（20f 蓄力换 3 伤穿防，恰好从 4HP 斩到 1HP 并续上 12f 破势）。C 的蓄力最长，与「慢」一致。
- 角色差异**只改数值**，不新增按键或规则，保证「易上手」。
- B/C 已实现并由局外解锁（见 §8.3）；三人共用同一套按键与规则。
- 角色名、立绘、头像、台词、胜利/败北语音、符卡名与描述：全部 PLACEHOLDER，由人类提供。

### 9.2 对手

- 5 位**通用剑客原型**（代号 1–5），每位一个「剑型」性格参数组（§7.2），不做专属机制。

### 11.2 视角三选一（各 0.5–1 天）

| 方案 | 优点 | 风险 |
|---|---|---|
| A 侧视 2D（推荐） | 判定可读性最好，最稳，工作量最小 | 画面较平 |
| B 斜俯视 | 更有「道场」空间感 | 遮挡与深度排序问题 |
| C 特写/电影感 | 表现力强，适合宣发截图 | 判定可读性差，易误判 |

- 结论写入本文变更记录；`DuelSim` 不依赖视角，换视角不改判定。

### 11.3 美术与音频边界

- 美术、音乐：人类提供；AI 不生成。
- **音效/环境音**：可检索并拉取 **CC0 / 明确可商用**的第三方素材，由人类试听确认后入库；AI 不生成音频。来源、作者、许可、链接逐条登记（见 `docs/audio-assets-plan.md` 与 `ai-disclosure.md` §6）。
- UI 音效可用 `addons/kenney_interface_sounds`（CC0）。
- 战斗音效与环境音在 M1 提前准备，避免后期缺稿；未选定前用静音/轻占位，不阻断开发。

### 11.4 HUD 与信息层级

- 顶部：双方 HP（短条/点）、心流条（带三档刻度）、场次（第 n/5）。
- 礼让结束：居中显示约 0.7s 的「开始」提示（`ui.round_start`，PLACEHOLDER）。
- 中央：只在前兆、心流升/降档时给极简提示；优先用符号/光效，文字版 PLACEHOLDER。
- 底部：操作提示仅在首战出现，之后隐藏。
- 调试层：状态名、剩余帧、判定窗、心流数值（仅开发期）。
- 可访问性：心流档位用形状/亮度区分而非只靠颜色；屏震可关；提示强度可调。

### 11.5 音频方向（由人类实现）

- 对峙：近乎静默，仅环境底噪与呼吸声，让「静」成立。
- 前兆：极轻的衣料/踏地声；真、假前兆的音色要有细微差别（可辨识但不直白）。
- 四个核心音必须清晰区分：斩中、被架、刃鸣、受击。
- 心流升档：短促上扬；降档：低频闷响。
- 收刀/胜负：留 1–2 秒余韵，不急着切结算。
- UI 音效：Kenney CC0 可直接用。
- **素材清单（初版）**：斩（whoosh/draw）、刃鸣（metal clash）、被架（metal thud）、受击（cloth/flesh hit）、衣料/踏地、呼吸、心跳、收刀（sheath click）、环境风声 loop、道场室内底噪 loop。
- **检索与入库**：候选来源、许可核对与下载记录见 `docs/audio-assets-plan.md`；命名 `sfx_<类别>_<变体>.ogg`，循环素材加 `_loop`；原始下载保留在 `assets/audio/_sources/` 便于复核许可。
- **许可红线**：只用 CC0 / CC-BY（需署名）/ Pixabay、Mixkit 等明确可商用许可；不用 NC、不用「仅个人使用」、不用来源不明素材。Mixkit/Pixabay 原始文件不入公开仓库，仅可进构建产物（见 `docs/audio-assets-plan.md` §2）。
- **验收**：人类试听选定；响度归一化到约 -16 LUFS；循环点无爆音；除环境音外单条 < 1 秒。
- **已接入（2026-10-20 灰盒第一版）**：`DuelAudio` 订阅 `state_changed`/`hit_landed`/`attack_blocked`/`clash_happened`/`guard_whiffed`；斩、拔刀、被架、完美格挡、刃鸣、受击、衣料、开始提示、UI 点击、环境风声已接；全部 CC0（Kenney + OGA SketchMan3）。映射与来源见 `docs/audio-assets-plan.md` §10、`assets/audio/CREDITS.md`。仍缺呼吸/心跳/收刀/室内底噪，受击音偏卡通，待人类试听替换。

### 12.2 核心类

| 类 | 类型 | 职责 |
|---|---|---|
| `DuelSim` | `RefCounted` | 纯逻辑：状态机、帧计数、判定、心流、HP；每物理帧 `tick()` 一次 |
| `FighterState` | `RefCounted` | 单方状态、剩余帧、心流、HP、输入缓冲 |
| `FrameData` | `Resource` | 帧数据与心流参数，`@export` 可调 |
| `DuelAi` | `RefCounted` | 意图决策、性格权重、固定种子 RNG |
| `AiProfile` | `Resource` | 攻击欲、虚招率、反应、惩罚率、节奏 |
| `RunState` | `RefCounted` | 阶梯、HP、心得、种子、当前场次 |
| `MetaSave` | `RefCounted` | 金币、解锁、设置、统计的读写与迁移 |
| `DuelController` | `Node` | 读 GUIDE 输入 → `sim.press()`；`_physics_process` 调 `sim.tick()`；转发事件 |
| `DuelView` | `Node2D` | 纯表现：动画、刀光、屏震、音效 |
| `Hud` | `Control` | HP/心流条、场次、提示 |

### 12.3 事件流

```
GUIDE 输入 ──► DuelController ──► DuelSim.press()
                                      │
                                 DuelSim.tick()
                                      │
                    ┌─────────────────┼──────────────────┐
                 DuelView            Hud              Audio
```

- `DuelSim` 用信号暴露事件：`state_changed`、`hit_landed`、`attack_blocked`、`clash_happened`、`flow_changed`、`duel_finished`。
- **高频战斗事件不走 EventBus**（避免每帧字符串派发）；EventBus 只承载流程级事件（开战、结算、切场景）。
- 场景切换/菜单走 `mc_game_framework` 的 `UIManager`。

### 12.4 时间与确定性

- 所有逻辑在 `_physics_process`（60 Hz）；`sim.tick()` 每帧一次，参数为空。
- 计时一律 `int` 帧，不用 `delta` 浮点累加，避免边界抖动。
- 随机只用 `RandomNumberGenerator`；`seed = run_seed ^ duel_index`，AI 决策可重放。
- 表现层可以用 `delta` 插值，但不回写逻辑。

### 12.5 数据资源

- `FighterData`、`AiProfile`、`UpgradeData` 全部 `Resource` + `@export`，放 `resources/data/`。
- 调参不进代码；新增角色/对手只加 `.tres`。
- 可用 `mc_game_framework` 的 `RegistryManager` 注册数据表（可选，不强制）。

### 12.6 插件使用

- **GUIDE**：输入 action / context；不直接 `Input.is_action_*`，不硬编码键名。手柄/鼠标与键盘通过同一 action 的多条 `GUIDEInputMapping` 并存。
- **mc_game_framework**：`UIManager` 管菜单栈；`RegistryManager` 注册 UI/心得/解锁注册表；`EventBus` 只做流程事件。
- **sound_manager**：UI 与战斗音效播放、总线音量。
- **注意**：`project.godot` 现已写入 `[autoload]`：RegistryManager、EventBus、I18NManager、SoundManager、GameBootstrap、GUIDE；headless 运行同样可用。

## 13. 输入方案（GUIDE）

- Actions：`duel_attack_p1`、`duel_guard_p1`、`duel_attack_p2`、`duel_guard_p2`、`duel_restart`、`duel_pause`、`duel_offer_1..3`。

- **键鼠 + 手柄并存**：每个动作可挂键盘、鼠标、手柄多条 `GUIDEInputMapping`；P1 鼠标左/右键 = 斩/架，手柄 1 的 A/B 同时可用；P2 默认键盘，检测到第二手柄时追加手柄 2 的 A/B。手柄键在设置页可逐项改绑，写入 `settings.joy_buttons`；冲突只在同一手柄作用域内拒绝（P1 动作之间、P2 动作之间、暂停/重开全局）。
- 设置页可逐项改键、检测冲突、恢复默认；HUD 操作提示按当前绑定动态生成。
- 语言：`localization/zh_CN.json` 与 `localization/en.json` 均为 **151 键**（2026-10-21 起；早期为 131 键），集合完全相同；设置页切换后 `I18NManager.set_language` 即时生效。其中 44 条内容文案仍是占位（见 §15.2），其余为通用 UI 标签。
- UI 动作（菜单/商店/设置/暂停/奖励）走 Godot 内置 `ui_accept`/`ui_cancel`/`ui_up/down/left/right`；`GameBootstrap` 在启动时为 A/B 与方向键补 `device=-1` 的手柄事件，任意手柄都能操作界面。
- **手柄兜底**：GUIDE 的 `joy_index -> device_id` 表在 autoload 初始化帧可能为空，已连接手柄不会再次触发 `joy_connection_changed`；`GameBootstrap` 下一帧强制刷新一次，`DuelController` 始终给 P1 建第一个手柄映射、双人给 P2 建第二个，并额外用 `_input(event)` 按 `event.device` 分发（P1/P2 隔离；暂停 200ms 去抖）。GUIDE 与兜底同时触发时只置位队列，不会重复出招。
- 构建版本：`project.godot` 的 `config/version` 为 **`0.1.0`**（2026-10-21 起，语义化版本；此前为 `0.0.0`），游戏内「关于」页显示同一版本号；GitHub Release 构建号为 `YYYY-MM-DD-NN`（UTC，NN 从 01 起按当天已有 tag 递增），由 `.github/workflows/build.yml` 生成 tag/Release 并上传 EXE。
- 测试：GUIDE 注入或 `GutInputFactory`，不硬编码键名。
