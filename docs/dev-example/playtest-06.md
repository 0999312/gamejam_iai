## 1. 反馈 1：删除残心显示

### 1.1 现象与解读

玩家开局第一眼在 HUD 顶部看到「第 1/5 场　金 0　残心 0」，其中「残心」是一个**没有任何教学、没有情感锚点、当前值恒为 0** 的术语。人类据此判断它会提高入门门槛，建议直接删掉显示。

这里的措辞是「删除**显示**」，不是「删除机制」——残心仍然参与局间成长（折算开局心流、心流下限、受击损失减免、架窗/反斩加值），删显示不影响任何判定。

### 1.2 现状（实测）

- **唯一显示点**：`scripts/duel/duel_hud.gd:79-80` 创建 `_run_info`，`:152` 定位在 y=152（顶部第三条信息行）；
  `:354-359` 是它唯一的写入点：

  ```gdscript
  _run_info.text = "%s %d/%d  %s %d  %s %d" % [
      _tr("ui.run"), run.stage_index + 1, RunState.STAGE_COUNT,
      _tr("ui.gold"), run.gold,
      _tr("ui.zanshin"), run.zanshin,
  ]
  ```

- **文案**：`localization/zh_CN.json:8` `"zanshin": "残心"`；`localization/en.json:8` `"zanshin": "Zanshin"`。
- **机制**：`scripts/run/run_state.gd:46` `var zanshin: int`；`:157-170` 折算开局心流、`flow_floor`、受击心流损失减免、架窗与反斩加值，上限 3 层。整个 `scripts/` 里 `zanshin` 的引用只剩注释和 HUD 那一行。
- **测试**：`tests/unit/test_run_state.gd` 有大量残心**机制**断言（不能改）；`tests/integration/test_duel_hud.gd` 没有断言顶部残心文本，删显示不会碰红任何现有测试。

### 1.3 判定：成立

- 删显示是**零机制风险**的改动。
- 残心的收益本来就通过「开局心流更高、心流下限更高、受击掉得更少」直接体现在心流条上，删掉名字不会让玩家失去因果反馈——只是不再用一个未解释的词去占位。
- 唯一需要讨论的是「局末奖励回路是否还看得见」（见 §1.4）。

### 1.4 待人类确认

- **A**：HUD 顶部整行只留「第 N/5 场　金 X」；（推荐）
- **B**：HUD 删，但在结算页加一行「残心 +1」（复用既有人类词条 `ui.zanshin`，不新写文案）；
- **C**：首场不显示、第 2 场起显示（实现最贵，不推荐）。

## 2. 反馈 2：占位提示加 L 键开符卡

### 2.1 现象与解读

玩家在对局里能按 L 放出符卡（`scripts/core/key_bindings.gd:11`），但 HUD 底部操作行和教程提示都没有告诉玩家这件事。人类要求在「占位提示」里补上 L 键的说明。

### 2.2 现状（实测）

**第一处：底部操作行**

- `duel_hud.gd:266-281` `_controls_text()`：没有设备元数据时回退 `ui.controls_versus` / `ui.controls`；否则取 `ui.controls_versus_template` / `ui.controls_template`，模板缺键时再回退；然后依次替换 `%a`（attack_p1）、`%g`（guard_p1）、`%d`（attack_p2）、`%f`（guard_p2）、`%r`（restart）、`%p`（pause）。
- **当前没有任何 spell / `%s` 的替换**，模板里也没有符卡位。
- 文案：`zh_CN.json:9-11`
  - `controls`：「J 斩 / K 架 / R 重开 / Esc 暂停 / 1–3 选心得」
  - `controls_template`：「P1 %a 斩 / %g 架　%r 重开　%p 暂停　1–3 选心得」
  - `controls_versus_template`：「P1 %a 斩 / %g 架　P2 %d 斩 / %f 架　%r 重开　%p 暂停」
  - `en.json:9-11` 一一对应。
- 结果：无论键鼠还是手柄，玩家在 HUD 上看不到符卡键；而 `KeyBindings.label()` 早就支持 `spell_p1` / `spell_p2`（默认 L / 小键盘 3 或 P，手柄 Y）。

**第二处：教程占位提示**

- `zh_CN.json:134-140` 的 `tutorial.start / guard / attack / flow / wait` 全部是 `[占位]` 前缀（登记为 T-12~T-16 / PH-07）。
- `duel_hud.gd:468-479` `_tutorial_text()` 按「开局窗 → 对手 COMMIT → 对手 RECOVERY → P1 心流 ≤20 → 默认」返回一个 key，**没有任何键位插值**，也没有「符卡可用」这一支。
- 也就是说：教程提示既没有提到符卡，也没有「按 L」的字面。

### 2.3 判定：成立（两处都缺）

- 第一处是**纯键位可见性**问题，改两个 JSON 模板 + 一处 replace 即可，不新增台词。
- 第二处是**引导时机**问题：玩家可能整局都没意识到符卡存在。教程提示里补一条「符卡可用」是合理的，但触发时机、优先级和文案都需要人类拍板（文案按项目规约不能由 AI 写）。

### 2.4 细节

- 符卡键默认是 L（P1）、小键盘 3 / P（P2），手柄 Y；改键设置页目前**没有**符卡改键行（`zh_CN.json:77-82` 只有攻击/格挡/暂停/重开），但 `KeyBindings` 的读写与冲突检测已支持 spell，后续要加行成本很低。
- 教程提示如果要加「符卡可用」，优先级应低于对手出刀警告（COMMIT / RECOVERY），否则会在最危险的时候刷出无效提示。

## 3. 反馈 3：均衡的符卡设计没有实际意义

### 3.1 现象与解读

角色 A（均衡）的符卡是「架势」（`spell_a`）：30 心流、10f 蓄力、60f 内格挡必判完美。玩家/人类认为它「没有实际意义」，建议按其他三张符卡（疾风连斩、崩山、关底终式）的表现重新设计。

### 3.2 现状数值（实测）

| 项 | spell_a 架势 | spell_b 疾风连斩 | spell_c 崩山 | spell_boss 终式 |
|---|---|---|---|---|
| 效果 | 60f 内架判必完美 | 直接落刀 | 直接落刀 | 直接落刀 |
| 伤害 | **0** | 20 | 30 | 30 |
| 穿防 | — | 是 | 是 | 是 |
| 蓄力 | 10f | 8f | 20f | 14f |
| 心流成本（面板 / 开局净耗） | 30 / 25 | 35 / 31 | 34 / 21 | 40 / 25 |
| 附加 | 架窗抬到 ≥30f | — | +12f 硬直 | — |

- 数值来源：`scripts/duel/spell_card.gd`（`flow_cost` / `cast_frames` / `amount`），`scripts/duel/duel_sim.gd:24-55`（结算常量），开局净耗按 `_add_flow` 的 `clampi(flow, flow_floor=15, max_flow=100)` 计算。
- 单刀伤害：A 10 / B 7 / C 15；血量 A 30 / B 30 / C 40。所以 20 / 30 点符卡伤害约等于「2–3 刀」，而 A 的符卡是 0 刀。

### 3.3 量化：为什么「没有实际意义」成立

**① 它不改变击杀所需刀数。** A 对 30HP 需要 3 刀（10×3）；符卡 0 伤害，击杀曲线完全不变。B 的符卡 20 伤 ≈ 2 刀多，C 的 30 伤 = 一管血。

**② 它的「增量收益」只有 +5 心流差，成本是 25 心流。**

- 普通格挡：`BLOCK_FLOW_GAIN = 7`（`duel_sim.gd:655-687`）。
- 完美格挡：`PERFECT_BLOCK_FLOW_GAIN = 12` + 连击加成 3/级（上限 9）。
- 符卡让一次格挡从普通变完美，净差 = **+5 心流**（不含连击）；要回本 25 心流需要 5 次完美格挡，而 60f 窗口内最多只够按两次架（每次架窗 30f，收架 8f）。
- 换句话说：**花 25 心流买一个「最多 +5 心流差」的窗口**，经济上是负收益。

**③ 它几乎不增加防守能力。** A 自己的架窗是 24f（+ 档位 0/4/8 → 24/28/32f），符卡把架窗抬到 `SPELL_STANCE_GUARD_FRAMES = 30`（`_enter_guard` 里的 `maxi(duration, 30)`）。在 CALM 档（32f）这甚至是**没有提升**的；在 SPREAD 档（24f）也只多 6f。

**④ 它甚至**制造**了额外风险。** `_has_spell_charge()` 把 `spell_perfect_until_frame > frame` 也算作蓄力：架势期间被砍中（没架住）会被当作「符卡被打断」——驱散、`spell_interrupted`、`SPELL_INTERRUPT_PENALTY = 12f` 硬直外加 hitstun。也就是说，开了符卡反而比不开更怕挨刀。

**⑤ 普通格挡已经给了同样的反击窗。** 任何格挡（普通或完美）都会设 `counter_until_frame = frame + GUARD_COUNTER_WINDOW(30)`，窗口内按斩出来的是「顺势斩」（`-6` 前摇修正）。符卡唯一多出来的就是「判定必完美」，而它连 10 点伤害都没有。

> 结论：这张符卡**不改变击杀曲线、不改变资源正负、不增加可持续防守能力、还提高了被打断的代价**。人类说「没有实际意义」，在数值上完全站得住。

### 3.4 判定：成立，需要重设计

理由不是「数值偏低」，而是**它没有新增规则级选项**（设计文档 §6.11 自己的红线：「收益必须规则级」「风险明牌可读」）。重设计方向见 [`balance-pass-06-plan.md`](balance-pass-06-plan.md) §3。

## 4. 三条反馈的关系

- 1 和 2 都属于「入门可读性」：一个删噪音，一个补缺失信息。它们不改判定，风险最低，应该先做。
- 3 属于「符卡设计」：其他三张都是「蓄力 → 自动落刀 → 穿防」，只有 A 是「蓄力 → 一段增益 buff → 无伤害」。**同构性**被打破后，玩家自然会把 A 当成「没用的那张」。
- 三条都指向同一个体验层结论：**A 的守型定位在规则上没有可兑现的进攻出口**。
