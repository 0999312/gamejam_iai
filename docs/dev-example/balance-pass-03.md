# 平衡 03：把「变招」打通（攻↔防的取消路径）

> 起因：第三方反馈「攻击转防的变招和防御转攻的变招在实际游戏中打不出来」，
> 以及「防御的前后摇让防御本身变成代价巨大的操作」。
> 本文只记录改动与实测，方案取舍见 `balance-pass-02-plan.md`。

## 1. 诊断：两条变招各自断在哪里

全部为 60Hz 逻辑帧（1f ≈ 16.7ms）。

| 路径 | 改前 | 人类的可用性 |
|---|---|---|
| 构 → 架（攻击转防） | 仅 `cancel_window = 5f`（83ms） | 低于反应下限（≈250ms），等于不存在 |
| 架 → 斩（防御转攻） | **不存在**：`_apply_action` 的 `GUARD` 分支走 `_: pass`，输入被直接丢弃 | 完全按不出来 |
| 架住 → 斩 | 只能等收架 7–9f 结束，再按普通前摇 18–21f | 从「叮」到落刀 400–500ms，常慢于对手恢复 |
| 收架中的预输入 | `input_buffer = 4f` < `guard_recovery` 7–9f | 预输入必然过期，表现为「按了没反应」 |

防御的固定占用：起架 1–2f（其间被打算命中）+ 架窗 18–22f + 收架 7–9f = **26–33f（433–550ms）**，
期间不能做任何事；空架还要扣 8 心流。所以「防御代价巨大」在数据上成立。

## 2. 改动

| 改动 | 数值 | 位置 |
|---|---|---|
| 构 → 架的取消窗口 | 5f → **10f（167ms）** | `fighter_data.gd` `cancel_window` |
| 架中按斩 | 立即收架出刀，扣 `cancel_cost = 5` 心流 | `duel_sim.gd` `_apply_action` GUARD 分支 |
| 架住后的反击预备 | **30f（500ms）**，从格挡成功那一帧起算 | `duel_sim.gd` `GUARD_COUNTER_WINDOW`、`_do_block` |
| 顺势斩前摇 | **−6f**（一次性，进构时消费） | `duel_sim.gd` `GUARD_COUNTER_COMMIT_BONUS` |
| 顺势斩不吃反斩 | `_enter_commit(fighter, allow_riposte)` | 同上 |
| 输入缓冲 | 至少活到硬直结束（`max(frame + input_buffer, 硬直结束 + 1)`） | `duel_sim.gd` `_buffer` |

设计约束：

- **顺势斩不加反斩**。挡住一刀本身已经换来对手 24–36f 硬直，再叠反斩（−10f）会把「架」
  变成白送一刀；−6f 刚好让 250ms 反应仍然成立（15f 反应 + 12f 前摇 = 27f < 32f 硬直）。
- **反击窗 500ms 而不是「收架那几帧」**。收架只有 7–9f，人类根本来不及；500ms 覆盖
  「看到叮 → 判断 → 按键」。
- **主动收架（架窗内按斩）仍可吃反斩**，因为那是放弃防御去抢刀，风险更高、回报也该更高。

### 2.1 架子是「按住」的，不是「按下就跑完」

初版把 `guard_duration` 实现成「按下后固定站桩 N 帧」，结果：

- 只想探一下的玩家被迫站满 20–24f，跑满还要吃空架 −8 心流 + 7–9f 收势；
- 看到虚招想收手也收不了，等于每次架都是承诺。

现在改成**按住持续 / 松手立刻收**：

| 操作 | 结果 |
|---|---|
| 按住架 | 架子保持到「单次架上限」（`guard_duration`，含心流档位） |
| 松手 | **2f 收势（`RELEASE_GUARD_RECOVERY`）**，不扣心流、不算空架 |
| 按满上限 | 仍走 `_finish_guard`：空架 −8 心流 + `guard_recovery` 7–9f |
| 架窗内按斩 | 立即收架出刀（扣 5 心流） |

数据流：`DuelSim.set_input(side, attack, guard, guard_held)`，`guard_held` 取 `-1`（AI/脚本单次
`press`，按满上限）/ `0`（松手）/ `1`（按住）；`duel_controller` 用 `GUIDEAction.completed`
跟踪松手。AI 仍走 `press`，行为不变。

这样「点按架」是低成本的试探（风险是 2f 收势 + 架窗只有几帧），「按住」才是承诺——
符合「架是瞬间动作、不是一段动画」的直觉。

## 3. 实测（机器人矩阵，3 seed × stage 0/2/4）

| 机器人 | 均衡 | 快剑 | 重剑 |
|---|---|---|---|
| 无脑连砍 | 0% | 0% | 67–100% |
| 只架 + 帧完美反击 | 100% | 67% | 100% |
| 只架 + **250ms** 反应反击 | 100% | 67% | 100% |
| 只架 + 350ms 反应反击 | 33–67% | 67% | 33–67% |

结论：250ms 反应足够拿到反击收益，350ms 开始掉出窗口——窗口边界符合「人类反应 200–300ms」的设计目标。

## 4. 遗留风险（需要人类决策）

1. **「只架不攻」对 NORMAL AI 仍然 100% 胜**：AI 在玩家架住时的出刀会被稳定反击，
   而 AI 缺少「骗架」手段（现有虚招只是自己构中取消，不针对玩家的架）。
   下一步可能需要给 AI 加「延迟出刀 / 假动作骗架」，或降低架住反击的收益。
2. **重剑连砍仍强**（同 02 文档 §7）：15 伤 ×2 刀 = 30，属批复数值的必然。
3. **教学关 AI guard_chance 0.45 偏高**，新手可能一直挨架。
