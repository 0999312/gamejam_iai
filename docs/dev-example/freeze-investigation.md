# 提交版卡死排查 · 2026-11-22

**范围：** 测试反馈集中在主菜单，未排除对局。下列两条可复现路径都是界面仍在运行、操作却走错了地方；没有故障机日志，不能认定它们解释了所有报告。初版诊断时仅作记录；2026-11-22 的修复与验证见文末「赛后修复」。

## 可复现的路径

1. **退回主菜单后手柄失焦。** 1280×720 实窗，主菜单「开始」按 A → 模式选择按 B 返回 → 十字键下、A。返回时焦点为空，按下方向后仍为空，A 没有再次打开模式选择；其间引擎仍推进了 12 个处理帧。此时已没有打开的面板，按一次键盘 Tab 能回到原先的「开始」，A 恢复；鼠标直接点「开始」也有效。菜单仅在[创建按钮时抓焦](../../scripts/ui/menu.gd#L121-L122)，[弹栈](../../addons/mc_game_framework/autoload/ui_manager.gd#L132-L147)在栈空时隐藏遮罩，没有把焦点还给不在面板栈中的主菜单。
2. **设置盖到对局上。** 主菜单 → 设置 → 关于 → B 返回。设置仍是栈顶，但焦点为空。此时 Tab 落在背后的主菜单，再按 A 会打开模式选择；继续选单人并确认角色后，当前场景已是对局，原设置面板仍可见且在栈顶。设置从[可见下层恢复](../../addons/mc_game_framework/autoload/ui_manager.gd#L140-L147)时未重新抓焦；[进入对局](../../scripts/ui/menu.gd#L171-L192)只关闭本流程的选择面板。**不要用 Tab 修这一条**：先用鼠标点可见设置页的「返回」，完全退出设置再开局。
3. **设置页同步写盘，不是静置菜单的解释。** [计时器先挂到设置面板](../../scripts/ui/settings.gd#L42-L64)，随后的[界面重建](../../scripts/ui/settings.gd#L179-L184)移除并释放所有直接子节点。实测就绪后计时器数为 0，同一帧连续将主音量设为 21%、22%、23%，每次立刻从独立测试存档读回 0.21、0.22、0.23。原有 350 ms 合并写盘实际走了[即时保存分支](../../scripts/ui/settings.gd#L491-L512)，且每次调整都会[重新请求窗口模式](../../scripts/core/game_bootstrap.gd#L167-L192)。慢盘或安全软件扫描可能放大停顿，但本次**没有测到永久阻塞，也没有测量故障机 I/O 延时**。

## 测了什么

- 版本：源码标签 `v0.1.0-submit`（`e778e2a`）；用[提交清单](../gamejam/submission-checklist.md#L136-L146)所指的原包解压运行，不把编辑器当前工作树当提交版。原 ZIP SHA-256：`60fa35b695cee013721658ecca11a06681a092ffe1f01cfb4a6e249ef941c66f`；EXE SHA-256：`adedb3191dbe78e903794ad04280a54e0d7a8f16ca2285b800d51728d5b2e2d9`。所有本机试跑使用临时用户目录。
- **原 Windows 包**：同一台 RTX 4060 Laptop，1280×720、上限 60 FPS，Vulkan Forward+ 和 OpenGL Compatibility 各跑两条路径。各自在主菜单静置 600 帧，FPS 采样均为 60；各自通过真实窗口的菜单和选角进入单人对局，全流程 1200 帧，进入对局后的 FPS 采样范围 41–60。四次退出码均为 0。没有更换物理 GPU，不能由此排除特定设备或驱动问题。
- **原包默认设置下的额外静置**：不改分辨率、不另设帧率上限，连续 180 秒，177 次 FPS 读数为 234–241（中位数 240），可以正常关闭，游戏退出 0。但外部 Windows `IsHungAppWindow` 在 180 次采样中有 175 次返回真，因此以该标记判定卡死的第一版探针退出 1。另一次用同一可见窗口句柄复核，两次标记为真时 `WM_NULL` 都在 15 ms 内返回；随后正常菜单输入进入单人对局、游戏退出 0。这说明**本机这条“未响应”标记不能代替帧或输入证据**，并非证明故障机也是假警报。
- **提交标签的隔离副本**：Godot 4.7.2、GUT 9.6.0，实窗探针用方向键/手柄事件、焦点所有者、面板栈、当前场景及即时读盘区分上述路径。3 个观察用例、25 个断言通过，**是成功复现缺陷，不是修复通过**。副本进入对局时出现 Spine 骨架回退警告；原 Windows 包两后端日志均记录骨架资源加载完成，不能把副本告警当成故障机证据。
- 主菜单和对局都绘制[雨夜背景](../../resources/shaders/rainy_night.gdshader)。从未打开面板、从未调整音量时，不能用上面三条操作解释整幅画面停住；无窗口测试也不覆盖实际显卡驱动。

## 故障机下一次怎么取证

1. 保留原包和原设置，不删除存档。把随排查交付的独立 Windows 采集脚本放到**解压副本**的游戏 EXE 与原 DLL 旁，双击选 **1（默认）**，保持采集窗口开启；不替换任何游戏文件，也不需要管理员权限。采集器只在本机启动原游戏并记录进程；游戏本身仍会像平时一样使用自己的存档。
2. 复现时记下本地时刻和最后一次操作，尤其是**有没有进过设置或模式选择**。若窗口还能显示，观察雨是否在动、鼠标能否点可见按钮、键盘和手柄是否同时失效；若 Windows 也提示未响应，先留几秒进程采样，再结束游戏。不要为了取证反复强制结束机器。
3. 控制台显示的 `%TEMP%\iai-diag-…` 是本轮目录。回传其中的 `engine.log`（驱动、FPS 及错误）、`process.csv`（约每秒采一次的窗口响应、累计 CPU 秒和工作集）、`session.txt`（模式、时间、EXE 哈希及可获得的系统信息）。可先遮盖日志里的本地用户名、路径；不用上传存档、内存转储或游戏包。
4. 若连雨景也停住，用**同一分辨率、同一操作和相近时长**选 **2（只改 OpenGL）**再测；若仍需隔离声音，再选 **3（默认渲染，只改 Dummy 音频）**。选择 3 时无声是预期行为。单次没复现不能归因；引擎 FPS 行停止时要对照独立进程采样与记录的时刻。Windows「响应」只代表消息泵状态，不能单独证明游戏逻辑正常。

不使用采集脚本也可以：在游戏解压目录打开 PowerShell，用 `.\iai.exe --verbose --print-fps --log-file "$env:TEMP\iai-default.log"` 启动。这样只有引擎日志，没有独立进程采样。没有带参数启动时，可查 `%APPDATA%\iai\logs\godot.log`；不保证含 FPS。

## 赛后独立版本可采用的修复与验收（未实施）

- 在项目 UI 层记录打开面板的控件；弹出时将焦点还给当前可见栈顶或主菜单。栈顶存在时不让底层菜单接收导航/确认；切入对局前清理属于菜单流程的残留面板。不改第三方插件源码。回归要求：只用手柄连续开关模式选择、从关于退回设置时焦点不越层、进对局时设置不可见。
- 设置页只重建 UI 内容容器，不销毁计时器；音量变化只应用音量，不重设窗口模式。回归要求：一轮连续拖动至多合并写盘一次，关闭面板时最终值不丢；切换语言后再次验证。

## 赛后修复（2026-11-22，已改代码）

- **窗口模式**：`GameBootstrap.apply_settings()` 拆分音频与窗口模式；只在目标模式与当前模式不同时才 `call_deferred` 应用，音量/静音/商店切换不再重设窗口。
- **设置写盘**：`SettingsPanel._build_ui()` 跳过 `_save_timer`/`_wipe_timer`，音量滑条改走 `apply_audio_settings()`，恢复 350ms 写盘防抖。
- **全屏渲染**：雨夜背景改为 1280×720 `SubViewport` 再放大，降低全屏逐像素 shader 成本。
- **失焦恢复/安全模式**：`NOTIFICATION_APPLICATION_FOCUS_IN`/`NOTIFICATION_WM_WINDOW_FOCUS_IN` 补一次目标模式；新增 `user://session.lock`，异常退出后的下一次启动强制窗口化。
- **验证**：GUT **323/323（1376 asserts，40 脚本，退出码 0）**；本地 release 导出 `iai.exe` 121,230,040 B + dll 1,774,592 B；实窗全屏 1707×1068、最小化/切后台分钟级冒烟 `responding=True`；全屏截图 `build/smoke-fullscreen2.png`。**未做 10 分钟与非开发机验证**；本地导出包未观察到 `session.lock` 生成，安全模式待远端构建复核。
